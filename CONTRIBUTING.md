# Contributing to PragyaPortfolio

Thank you for your interest in contributing to this project.

This document explains the workflow to follow when reporting bugs, suggesting features, or contributing code.

## Before You Start

Before working on a change:

1. Check the existing issues to see whether the problem or feature has already been reported.
2. Check whether someone is already working on the issue.
3. For significant changes, discuss the proposed approach in the issue before starting development.
4. Wait for the issue to be clarified and approved before beginning implementation.

## Creating an Issue

Create an issue when you:

- Find a bug.
- Want to suggest a new feature.
- Identify an improvement to the project.

Provide enough information for the issue to be understood and reproduced.

## Development Workflow

Once an issue is ready to be worked on:

1. Create a branch for the issue.
2. Use a clear branch name that describes the change.
3. Implement the change.
4. Test the changes locally.
5. Make sure existing functionality has not been broken.

## Pull Requests

When the implementation is complete:

1. Push your branch to GitHub.
2. Open a Pull Request against the `main` branch.
3. Clearly describe what was changed and why.
4. Link the related issue.
5. Wait for the Pull Request to be reviewed.
6. Address any requested changes.
7. Make sure all required checks pass.
8. Once the Pull Request is approved, it can be merged.

## Code Review

Pull Requests should be reviewed before they are merged into `main`.

Reviewers may check:

- Correctness of the implementation.
- Code quality.
- Testing.
- Documentation.
- Potential impact on existing functionality.

Contributors should address review comments before the Pull Request is merged.

## Testing

All changes should be tested locally before opening a Pull Request.

If a change introduces or modifies functionality, appropriate tests should be added or updated where applicable.

## Questions

If you are unsure about how to contribute or how to approach a change, raise an issue or discuss the question in an existing issue before starting implementation.
